# Roadmap and Jan Portal Visual Prototype

Open [`index.html`](index.html) in a browser. The prototype is self-contained,
uses no external assets, and contains synthetic data only.

The **Plánovací katalog** tab renders a deterministic asset
(`planning-data.js`) generated by
[`scripts/generate_planning_asset.py`](../../../scripts/generate_planning_asset.py)
from [`planning/catalog.json`](../../../planning/catalog.json). The catalog is the
single derived source of status truth; the validator
([`scripts/validate_planning.py`](../../../scripts/validate_planning.py)) is the
gate. Markdown plans and the decision register remain authoritative.

The **Rozhodnutí** tab renders `planning/approvals.json` and separates human
approval, technical validation, implementation permission, and real-data
activation. Validate and regenerate it with:

```bash
./venv/bin/python scripts/validate_approvals.py --json
./venv/bin/python scripts/generate_approval_asset.py
```

The browser exports a JSON receipt but cannot silently modify repository
authority. A receipt must be reviewed, inserted into the register, and validated.

This panel works directly via `file://` (the asset is a plain global, no
`fetch`/CORS). If your browser restricts local scripts, serve the folder:

```bash
python3 -m http.server 8000 --directory docs/prototypes/roadmap-portal
# then open http://localhost:8000/
```

Regenerate the asset after editing the catalog:

```bash
./venv/bin/python scripts/generate_planning_asset.py
./venv/bin/python scripts/validate_planning.py
```

It demonstrates:

- three equivalent roadmap views: milestone journey, workstream board, and dependency map;
- a decision-status panel;
- Jan portal dashboard, OCR confirmation, worker/assignment, and A1 readiness screens;
- the confirmed simple OCR behavior: the logged-in uploader corrects or confirms values and the action is attributed to that user.
- the approved distinction between the sole real-data activation gate and non-blocking server-readiness work.

This is the seed of the living visual planning cockpit and remains derived,
synthetic presentation—not application architecture, production code, or an
independent source of status. PLAN-INFRA will bind its planning views to a validated
repository catalog. Product implementation should reproduce accepted behavior
using Django templates and progressive enhancement rather than copying prototype
JavaScript into production.
